# OVYRO Ops

Internal operations workspace for OVYRO client delivery, lead management, and retainer tracking. Built with Next.js App Router and prepared for deployment from GitHub to Railway.

## Current capabilities

- Dashboard, client directory, onboarding tasks, lead pipeline, client content, and resources.
- Admin sign-in plus database-backed team accounts. Owners can create active accounts with an email and password, edit account details, reset passwords, and remove accounts. Passwords are stored as scrypt hashes.
- Role-based workspace tab assignments and per-member client assignments. Team navigation and client lists are filtered from the signed-in account.
- Client account owner selection from the current workspace team list.
- Shared PostgreSQL persistence for clients, onboarding tasks, leads, client content, resources, and role definitions. Team credentials and login access are also stored in PostgreSQL.
- All monetary amounts and defaults use Indian rupees (INR).

## Important data boundary

Client, task, lead, content, resource, and role data is shared through PostgreSQL across browsers using the same running app. Existing customized browser data is imported when an owner opens the updated app and the shared workspace has not been initialized. Team reads are filtered by assigned clients and tabs, and team updates are merged within their assigned client scope. Workspace profile and onboarding workflow settings remain browser-local. Review role and client assignments carefully before using this for sensitive live client data.

## Run locally

Requirements: Node.js 22+ and PostgreSQL.

Create a local database (for example, `createdb ovyro_ops_dev`), set `DATABASE_URL` in `.env.local`, then run:

```bash
npm install
npm run admin:configure  # configures the owner; password input is hidden
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). The admin configurator preserves an existing `DATABASE_URL` entry.

## Environment variables

- `OVYRO_ADMIN_EMAIL`: owner login email.
- `OVYRO_ADMIN_PASSWORD_HASH`: salted scrypt hash generated by `npm run admin:configure`.
- `OVYRO_SESSION_SECRET`: random signing secret generated by the same command.
- `POSTGRES_URL` (or `DATABASE_URL`): PostgreSQL connection string. `POSTGRES_URL` takes precedence when both are set, matching Vercel database integrations. The app initializes the team-account table automatically.

Team accounts require PostgreSQL. Owners create a member with a minimum 12-character password; the account is active immediately. Editing a member with the password field blank leaves the current password unchanged. To change an account email or password, the owner edits that member's account. The previous email/password stop working after the next sign-in.

Never commit `.env.local` or paste the database connection string into source code. For Railway, attach a PostgreSQL service and set its connection string as `DATABASE_URL`, then configure the three owner variables as Railway service variables. Railway deployment is not configured yet.
